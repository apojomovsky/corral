# 03: the muse runtime adapter

Status: design, not built. This doc fixes the third adapter, `muse`
(the Muse Code CLI), next to `omp` and `opencode` in
`src/corral/runtimes/`. Nothing here changes the launch, resume, tail or
stop flow in `src/corral/launch.py`, the unit model, the registry,
admission, exit codes, or any CLI verb, so `README.md` needs no change.
The only index change is the row for this doc in `docs/README.md`.

Conventions below: "observed" means the author ran it on the dev host
with read-only probes (`--help`, `muse exec --provider echo` in a
scratch directory under the system temp dir, `muse model-profile show`,
`muse usage --json`). No real model call was made, so anything that
needs one is marked UNVERIFIED with a safe way to learn it. Quota
figures seen during probing are deployment data and are not repeated
here, only shapes. Home paths below are generic stand-ins:
`~/.config/muse/` for config, trust and auth, and
`~/.local/share/muse/` for sessions and state.

## 0. Where it fits

One new module, `src/corral/runtimes/muse.py`, exposing the same
`Runtime` protocol as the other two (`argv`, `env`, `write_config`,
`with_models`, `resume_handle`, `activity_file`), plus two small
helpers this runtime needs: `resolve(session_id)` (session id to
session file) and `classify(returncode, stderr_text, stream_text)`
(provider error classification, section 5). `activity_file(session)`
returns the unit's `out.log` path when present and `None` otherwise,
exactly like the opencode adapter, because `launch.py` tail calls it
unconditionally; without it a muse session would crash `corral tail`.
`runtimes/__init__.py` gains the name:
`NAMES` becomes `("omp", "opencode", "muse")`, `get("muse")` returns the
adapter, and `agents.runtime` accepts `muse`. `DEFAULT_RUNTIME` stays
`omp`; `record`/`recorded` are unchanged. `settings.PROVIDERS` already
lists `corral.runtimes`, and this design adds no new setting (section
1), so settings need no change.

Model ids: `quota.chain_provider` takes the part before the first `/`,
so a chain entry `muse/muse-spark-1.3` names provider `muse` and the
adapter passes the part after the slash as `--model`. The strip has
one owner: a tiny `models.bare_id(entry)` returning the part after
the first `/` (a bare id with no slash passes through unchanged).
`with_models` keeps the full chain entry in `config["model"]`, and
`argv` applies `bare_id` when building `--model` from either the
config model or the `model=` override, which `launch.py` passes
unstripped as today. The accounts file
carries one `[[provider]]` named `muse` with a muse quota reader
(section 6). The model id `muse-spark-1.3` is in the on-disk catalog:
observed, `muse model-profile show muse-spark-1.3 --effort high`
resolves it offline with default effort `high`.

## 1. The argv: worker, reviewer, resume

Worker (one headless run; line breaks for reading only):

```text
muse exec --json --prompt-file <session>/prompt.md
  --model <id> --contributor-mode on --session-id <uuid>
  --yolo --no-foreign-personal-context --disable-request-user-input
  --reasoning-effort high --parallel-tool-calls
```

Reviewer: the worker argv plus `--disable-write`.

Resume: the worker argv with `--session-id <existing uuid>`, a new
`--prompt-file` carrying the message, and `--model` only when the
caller overrides the model.

What each flag is, and the evidence:

- `--json`: fixed. Stdout is the JSONL event stream, one record per
  line with `payload_type`, `payload`, `sequence`. The unit's `out.log`
  captures it, so tail reads `out.log` exactly like the opencode
  adapter does. Notices (`muse: ...`) go to stderr, never stdout.
  Observed on every echo run.
- `--prompt-file <session>/prompt.md`: fixed. The prompt file is the
  one `_write_session` already writes. Observed: `--prompt-file` with a
  positional prompt is refused (exit 2, `--prompt-file cannot be used
  with inline prompt text`), so the adapter never takes the positional
  form. `runtimes.check_prompt` still applies: a prompt starting with
  `-` would read as a flag.
- `--model <id>`: from the models declaration. `with_models` lays the
  live chains over the per-launch config and the adapter passes the
  default role's head (via `models.primary`, as opencode does), with
  the `muse/` provider prefix stripped through `models.bare_id`.
  A `model=` override takes the same path: `muse/other` and a bare
  `other` both yield `--model other`. Observed: `--model` is refused
  under `--provider echo` (`--model requires --provider meta or
  local`), and its shape is verified in `muse exec --help`. An end to
  end run with `--model` needs a real call, so the value flow is
  UNVERIFIED at runtime but the flag shape is verified.
- `--contributor-mode on`: fixed. Observed in the top-level `--help`:
  a per-run override that is never persisted. The adapter passes it
  explicitly so a headless run never depends on the home config.
- `--session-id <uuid>`: fixed, generated by corral up front as a
  uuid4 at launch and recorded in corral's own session dir (section
  3). Observed: a non-UUID id is refused (exit 2, `invalid
  --session-id ... expected a UUID`).
- `--yolo`, `--no-foreign-personal-context`,
  `--disable-request-user-input`: fixed unattended set. Observed:
  accepted under `--provider echo`, exit 0. `--yolo` disables approval
  and the sandbox and trusts the workspace for the run only (help
  text); `--no-foreign-personal-context` keeps personal rules and
  skills out; `--disable-request-user-input` keeps the agent from
  blocking on a question.
- `--reasoning-effort high`: fixed. Observed: the default is already
  `high` (`muse exec --help`), and the flag is refused under
  `--provider echo` (meta-only), so its runtime effect is UNVERIFIED
  but its shape is verified. It is fixed rather than a setting,
  following the `omp.FORCED` precedent: one fact, one place, and no
  new settings surface. A project that needs another tier is a later
  setting, not this design.
- `--parallel-tool-calls`: fixed on. Observed: refused under
  `--provider echo` (meta-only), shape verified in `--help`.
- `--disable-write`: fixed for reviewers only. Observed: accepted
  under `--provider echo`, exit 0.
- `max_time`: accepted by the protocol, ignored by the adapter. The
  exec help shows no time flag (only `--max-model-steps` and
  `--max-tool-output-bytes`, which this design leaves at defaults), so
  like the opencode adapter the muse adapter takes `max_time` and sets
  nothing from it. The unit's `RuntimeMaxSec` (`RUNTIME_MAX_S`) still
  bounds the run.

Settings versus fixed, in one line: the models declaration picks the
model; every flag is fixed. No new `corral.toml` setting.

## 2. Per-launch overlay and the home config it never touches

Per-run settings travel as `-c KEY=VALUE` (repeatable, values are
JSON). Observed: `-c model="muse-spark-1.3"` exits 0 under echo, while
an unknown key (`-c bogus.key=1`) refuses the run with exit 2
(`refusing run: unknown key`). Secrets are allowed only as whole-value
`${VAR}` references (help text); the adapter passes none.

`write_config` persists the effective per-launch config as `muse.json`
in corral's session dir with the existing atomic helper, as an audit
record. `argv` derives the run from it: `config["model"]` becomes
`--model`, every other entry becomes `-c KEY=<json>`. `env` returns no
home-pointing entries (there is no `OPENCODE_CONFIG` equivalent; `-c`
needs no pointer). `with_models` sets `config["model"]` to the default
role's head and keeps every other key, mirroring
`opencode.with_models`.

Proof it never writes the home config: by construction the argv
contains no path under `~/.config/muse/` or `~/.local/share/muse/`
and no flag whose help text persists anything (`--contributor-mode`
is documented per-run, `--yolo` trusts the workspace for the run
only, `--trust-workspace` is never passed and also does not save
trust). A test pins the full flag allowlist, so a future flag that
persists state fails the suite until the design is revisited. What a
normal run does write is its session log under
`~/.local/share/muse/` (section 3), which is muse's own behavior, not
corral writing config.

Workspace trust: observed with `--yolo`, stderr reports `workspace
trust: trusted source=run-flag`. Observed without it in a fresh
scratch directory, the echo run still exits 0 but reports the
workspace as untrusted with delegation unavailable. Whether a real
model run in a never-trusted worktree fails headless is UNVERIFIED
(no model call was allowed); the maintainer notes report that it
does. The design needs no `--trust-workspace` and no trust file
write either way: `--yolo` covers the run. The one follow-up is a
single real run in a fresh directory confirming the trust file is
unmodified (section 10, ticket T8).

## 3. Session files and tail

Session location from a session id, observed: an `exec` run with
`--session-id <uuid>` persists
`~/.local/share/muse/sessions/YYYY/MM/DD/<uuid>/session.jsonl`
(verified with `find` by id), plus a `cli-*.log`, a `cron.db`, lock
files, and a `subagent/` tree. The date is the run date.

- `resolve(session_id)` is the one helper that maps an id to its file:
  it globs `sessions/*/*/*/<uuid>/session.jsonl` and takes the newest
  by `(mtime, basename)`, the `omp.resume_handle` rule, so equal
  mtimes never depend on directory order, returning `None` when
  absent. One fact, one place.
- `resume_handle(session_dir)` does not scan: corral chose the uuid at
  launch, so launch records it in corral's own session dir (a
  `muse_session_id` file next to the `runtime` record) and resume reads
  it back. The scan exists for export and audit only: its named
  callers are a future `muse export` reader and offline audits.
  Launch and resume never call it.

Tail reads the unit's `out.log` (the `--json` stdout stream), not the
on-disk `session.jsonl`. This distinction was observed, not assumed:
under echo, stdout carried 35 records with `run.*`, `turn.*` and
`task.*` payloads, while the session file carried 70 records almost
entirely `runtime.*` shapes (`runtime.session`,
`runtime.command_intake.*`, `runtime.retained_fact`, and one
`session.end`); stdout is not a prefix of the file. The stream is the
activity; the file is muse's own record, read by `muse export` when a
full transcript is needed.

Payload types that matter for `tail.render`, observed under echo:

- `run.lifecycle.started`: carries the prompt; shown once as the run
  header.
- `run.output.delta`: carries `text`; the agent's visible reply,
  rendered like assistant text.
- `run.terminal.completed`: carries `terminal: completed`, `reason`,
  and final `text`; the run's last line.
- `run.usage`: carries `calls`, per-model token counts, and
  `allowance` (null under echo). Not activity; it feeds the quota
  tail-scan (section 6), not the display lines.
- `task.lifecycle.*` (`proposed`, `scheduled`, `started`,
  `completed`, `failed`): subagent roster noise under echo (reminder
  agents); skipped by the renderer. A tool call surfacing as a task
  event is UNVERIFIED (no tool ran under echo).

`tool.result` (with `tool_name` and
`correlation_facts.outcome`) is reported in the maintainer notes but
did not appear in any echo run, so its render rule is
designed-from-notes and UNVERIFIED: render `-> <tool_name> |
<outcome>` and collapse the rest, mirroring the omp/opencode
one-line tool format. Everything else (reconciliation records,
`session.run.linked`, `task.stream.linked`) renders to nothing. The
renderer stays total: unknown `payload_type` values and non-JSON lines
are skipped, as today.

## 4. Resume

Resume is `exec --session-id <existing uuid>` with the next prompt;
`muse resume` is interactive and is not used. Observed: a second `exec`
with the first run's uuid exits 0 and executes the new prompt in the
same session (its stream opened at sequence 2, continuing the session
log). A stderr warning noted the echo provider default model because
the first session recorded no model; the meta equivalent (model switch
mid-session) is UNVERIFIED.

Limits, verified:

- The id must be a UUID (exit 2 otherwise), so corral generates and
  records it; a resume never invents one.
- Prompt travels by `--prompt-file` only; file plus positional text is
  exit 2.
- Resume appends to one session log, so concurrent resumes of one id
  would interleave. corral already excludes that: resume runs under
  the same spawn lock with second admission as every other runtime.

UNVERIFIED: resuming a finished, GC-aged, or date-rolled session;
resuming across days (the date directory changes, `resolve` scans, but
no run crossed midnight in probing). Corral resumes only its own
recorded uuid for a live ticket, so a missing session file is a
launch error like any other runtime with no session to resume.

## 5. Provider error classification

Observed today: usage errors exit 2 with a one-line `muse:` message on
stderr (bad `--session-id`, unknown `-c` key, prompt-file plus
positional text, meta-only flags under echo). Success exits 0 with
`run.terminal.completed` (`terminal: completed`) as the last stdout
record.

Provider failures (auth failure, quota exhaustion, rate limit,
network failure) are UNVERIFIED: learning them needs a real call,
which probing forbids. The exported wire schema was checked and
covers only transport-level codes, so classification must come from
observed runs, not from the schema. The design therefore ships
`classify` with verified usage-error rules and an explicit unknown
default, and learns the rest as follows, cheapest and safest first:

1. Auth shape: one run with a revoked credential (no spend possible),
   recording exit code, stderr text, and the terminal event's
   `reason`. Expected: a failing terminal event plus nonzero exit;
   exact wording to be pasted into the classifier and its fixture.
2. Rate limit and quota wording: do not force them. The tail-scan
   already feeds every run's output to `parse_limit_error`; capture
   the first wording seen in normal fleet operation and add it with
   its fixture. A staging account with a tiny allowance is the
   fallback, only with maintainer approval for the spend.
3. Network failure: one run with the network path blocked at the
   sandbox level, recording the same triple.

Until a category is learned, `classify` returns `unknown` and posts no
quota mark: per `docs/02-accounts-quota.md` the ledger records no
guess. When learned, only quota and rate-limit wordings post reactive
marks through the existing `note_limit_error` path; an auth failure is
a login matter (the fix text points at the login flow) and never a
mark. Exit-code mapping for provider failures stays UNVERIFIED and is
not part of this design's contract.

## 6. Quota

The muse quota reader polls `muse usage --json`: no model turn, safe
to call on a schedule. Observed shape (values omitted as deployment
data):

```json
{"allowance": {"weekly": {"usedPercent": 0, "resetsAtMs": 0},
               "window": {"usedPercent": 0, "resetsAtMs": 0}}}
```

The reader maps `window` to one `Window(used_pct, resets_at)` and
`weekly` to a second window, with `resetsAtMs / 1000` as epoch
seconds. That is the whole provider-specific surface, and it fits
`docs/02-accounts-quota.md` unchanged: the reader lives in the host
ops root (never in corral), is named by the `muse` entry in
`accounts.toml`, gets credentials at call time, raises `ReaderError`
on failure, and corral ships no muse reader. `run.usage` in the event
stream also carries an `allowance` field, but it was null under echo,
so the stream is not a quota source; whether real runs populate it is
UNVERIFIED. The reader's `parse_limit_error` ships returning `None`
for every input until section 5 learns the wording; that gap is an
explicit ticket (T6), not a silent default: unknown text posts no
mark.

## 7. The single-version rule

Doctor pins the supported muse major exactly the way the opencode
entry pins major 1: a `system_deps.toml` entry with probe
`["muse", "--version"]`, the default version pattern, a `min` on the
observed 1.x line, `below = "2"`, a fallback path in the generic
install shape (`~/.local/bin/muse`, same stand-in style as the omp
entry), and an install command the maintainer confirms before this
doc's approval (installing a runtime binary needs the maintainer's
go-ahead; the doc proposes no command on its own). Observed:
`muse --version` prints a `1.4.x` version line the default pattern
matches. A future major is a cutover, not a dialect: one PR ports
`muse.py` and its tests to the new major and deletes the old support,
and the `below` bound is what starts failing loudly the day the
binary jumps ahead.

## 8. The sandbox

Honest posture: with `--yolo` the muse sandbox is off (help text says
so), and this design runs every agent that way. Observed host facts:
the binary exists with its Bubblewrap backend, every run prints the
Linux sandbox notice (user namespaces required) on stderr, and this
host sets the flag that restricts unprivileged user namespaces. The
shell-under-sandbox failure itself was not reproduced here (it needs
a model-driven shell call); it is reported in the maintainer notes
with the host flag as corroboration. What bounds an agent is
therefore the worktree (the run's cwd), the transient unit
(`RuntimeMaxSec` and the existing unit accounting), `--disable-write`
for reviewers, and `--disable-request-user-input` so a run cannot
wait on a human. That is weaker than a sandbox and the doc does not
pretend otherwise. The alternative (a host AppArmor change permitting
the sandbox's user namespaces) needs root and the human's go-ahead
and is out of scope for the adapter; if it ever lands, dropping
`--yolo` for `--disable-approval` is a one-line argv change with no
protocol impact.

## 9. Test plan: fakes only, at the single seam

No test runs the real `muse` binary, reads or writes a real home
config, touches the network, or uses the echo provider as an oracle.
`tests/suiteguard.py` already refuses all of that. Production seams,
one per tool: `binary()` is patched to `/fake/muse` (the existing
pattern); the quota reader takes an injected `run` callable and tests
pass a fake returning canned `muse usage --json`.

New `tests/test_runtimes_muse.py` (session dirs are temp dirs):

- argv: exact worker, reviewer (`--disable-write`), and resume
  (`--session-id` plus message file) lists; prompt starting with `-`
  refused; `--model` carries the stripped head, provider prefix
  removed through `models.bare_id`; a `model=` override takes the
  same path (`muse/other` and bare `other` both yield `--model
  other`).
- config: `-c` encoding (JSON scalars, whole-value `${VAR}`
  passthrough); unknown-key refusal is muse's exit 2, so the adapter
  test asserts the argv shape that produces it rather than running
  it; `write_config` round-trips through the atomic helper;
  `with_models` sets the head and keeps other keys; `env` has no home
  paths.
- home-proof: argv and env contain no path under `~/.config/muse/`
  or `~/.local/share/muse/`; the full flag allowlist is pinned, so an
  added persisting flag fails.
- sessions: `resolve` finds the newest `<uuid>/session.jsonl` across
  date dirs by `(mtime, basename)` and returns `None` when absent;
  `resume_handle` returns the recorded uuid; `activity_file` returns
  the session `out.log` path when present and `None` otherwise;
  `record`/`recorded`/`get("muse")` behave.
- doctor/deps: the `system_deps.toml` muse entry parses, and the
  `below` bound trips on a canned `2.x` probe and passes on `1.x`.

Extended `tests/test_tail.py` (canned lines, temp files):

- `run.lifecycle.started` shows the prompt; `run.output.delta` and
  `run.terminal.completed` show text; `run.usage`,
  `task.lifecycle.*`, reconciliation and link records show nothing;
  unknown `payload_type` and non-JSON lines show nothing.
- `tool.result` cases are added with the fixture the first real tool
  call produces (T8); until then the renderer test asserts such lines
  are skipped, not misrendered.

Extended `tests/test_launch.py` (existing fake seams only): launch,
resume, tail and stop of a muse ticket through fake `run`/`list_fn`
with a forced stop implementation, proving the adapter honors the
protocol (`max_time` accepted and ignored, `resume` passed through,
`activity_file` returning the session `out.log`, with a missing file
raising the no-activity `LaunchError`).

## 10. Implementation tickets

Each is one agent of work with its own tests; none needs a new
public interface beyond `agents.runtime: muse`.

- T1: argv and registration. Build `muse.binary`, `muse.argv`
  (worker, reviewer, resume), wire `NAMES`/`get`, keep
  `DEFAULT_RUNTIME=omp`. Acceptance: the argv tests in section 9
  pass; `get("muse").name == "muse"`; `make check` green.
- T2: per-launch config. Build `write_config`, `with_models`,
  `env`, `-c` encoding, the flag allowlist test. Acceptance: the
  config and home-proof tests pass; no new setting registered.
- T3: sessions and resume. Build the `muse_session_id` record,
  `resume_handle`, `resolve`, `activity_file`, and the launch/resume
  path through the existing fake seams. Acceptance: launch then
  resume in tests uses one uuid; `resolve` finds a canned date tree
  newest by `(mtime, basename)`; `activity_file` returns the session
  `out.log` when present and `None` otherwise; missing file is a
  launch error.
- T4: tail rendering. Extend `tail.render` with the muse rules from
  section 3 and its tests, with `tool.result` asserting skip until
  T8 lands its fixture. Acceptance: the tail tests pass, fed through
  `activity_file` (a missing file raises the no-activity
  `LaunchError`); omp and opencode rendering unchanged.
- T5: error classification. Build `classify` with the verified exit-2
  usage rules and the `unknown` default, plus fixtures cut from the
  observed stderr lines. Acceptance: usage fixtures classify; every
  provider category returns `unknown`; no mark path is reachable from
  `unknown` (a test asserts it).
- T6: quota reader (ops side, not corral). Write the host reader
  against `muse usage --json` with the section 6 window mapping, and
  `parse_limit_error` returning `None` with a comment pointing at T8.
  Acceptance: fake-`run` tests map a canned allowance document to two
  windows; failure raises `ReaderError`; the reader lives outside
  corral.
- T7: doctor and system deps. Add the `system_deps.toml` muse entry
  (install command confirmed by the maintainer first) and its tripwire
  tests. Acceptance: `corral deps` reports muse; canned `2.x` output
  fails with the cutover hint.
- T8: close the UNVERIFIED gaps. With maintainer-approved spend only:
  one real run each for `--model` value flow, `tool.result` shape,
  trust-file untouched in a fresh directory, auth/rate-limit/quota
  wording, and resume across a date roll. Acceptance: each gap in
  sections 1 to 5 is replaced by a fixture and a test, or restated
  with the blocking reason; no other code changes.
- T9: takeoff. Run the full suite with `TEST=1`, `make check`, and
  the takeoff ritual on a branch, then request review. Acceptance:
  green gates and a review record; no README change (no new verb),
  with the reason recorded in the PR body.
